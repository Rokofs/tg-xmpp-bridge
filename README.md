# Telegram ↔ XMPP мост

Пересылает текст и медиа между одним чатом Telegram и одним
собеседником/комнатой в XMPP (xmpp.jp, monocles.eu и любой другой
сервер с поддержкой HTTP Upload — этому требованию отвечает
подавляющее большинство современных серверов, включая те, что
используются с Monocles Chat).

## 1. Установка

**Linux / macOS** (терминал / bash):
```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

**Windows** (PowerShell или cmd — НЕ интерпретатор Python, не `>>>`):
```
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```
После активации в начале строки появится `(venv)` — значит всё верно.

## 2. Что нужно подготовить

### Telegram

1. Напишите **@BotFather**, создайте бота командой `/newbot`, получите токен.
2. Добавьте бота в нужную группу (или используйте личный чат с ним) и
   выдайте ему права администратора, если это группа — иначе он не
   увидит некоторые типы сообщений.
3. **Узнайте `chat_id` через сам бот** — это надёжнее сторонних ботов:
   - впишите в `.env` только `TELEGRAM_BOT_TOKEN`, оставьте
     `TELEGRAM_CHAT_ID` и XMPP-переменные пустыми;
   - запустите `python bridge.py` — бот стартует в ограниченном
     режиме (мост ещё не активен, но бот уже онлайн);
   - напишите боту команду `/chatid` в том чате/группе, который
     собираетесь мостить — он пришлёт число в ответ;
   - впишите это число в `TELEGRAM_CHAT_ID` в `.env`.

### XMPP

1. Зарегистрируйте **отдельный** аккаунт специально для бота, например
   на `xmpp.jp` или `monocles.eu` (через любой XMPP-клиент вроде
   Monocles Chat, Gajim, Conversations — там есть кнопка регистрации,
   либо через `xmpp-http-upload`/`in-band registration`, если сервер
   это разрешает).
2. У вашего основного аккаунта (в Monocles Chat) добавьте бота в
   контакты и подтвердите взаимную подписку (presence subscription) —
   иначе сообщения не будут доходить в обе стороны.
3. Если мостите в групповой чат (MUC) — узнайте полный JID комнаты
   (`room@conference.server`).

## 3. Настройка

Сначала (как описано выше) заполните только `TELEGRAM_BOT_TOKEN` и
узнайте `TELEGRAM_CHAT_ID` через `/chatid`. Затем допишите остальные
переменные (XMPP-часть) — см. `.env.example` для пояснений по каждой.

Как подставить переменные окружения из `.env`:

**Linux / macOS:**
```bash
export $(grep -v '^#' .env | xargs)
```

**Windows PowerShell:**
```powershell
Get-Content .env | Where-Object { $_ -notmatch '^#' -and $_ -match '=' } | ForEach-Object {
    $name, $value = $_.Split('=', 2)
    Set-Item -Path "env:$name" -Value $value
}
```

Либо проще — добавить в начало `bridge.py`:
```python
from dotenv import load_dotenv
load_dotenv()
```
(и `pip install python-dotenv`), тогда `.env` будет подхватываться
автоматически при каждом запуске, без ручного экспорта.

## 4. Запуск

```bash
python bridge.py
```

**Первый запуск** (без `TELEGRAM_CHAT_ID` и XMPP-переменных) — бот
в чате отвечает на `/chatid`, в консоли будет:
```
Мост НЕ активен — не заданы: TELEGRAM_CHAT_ID, XMPP_JID, XMPP_PASSWORD, XMPP_PEER_JID.
Telegram-бот запущен в режиме /chatid (напишите /chatid в нужном чате)
```

**После полной настройки `.env`** и перезапуска:
```
Telegram-бот запущен, жду сообщений в чате -1001234567890
XMPP: сессия начата, вошёл как bridgebot@xmpp.jp
```

Остановка — `Ctrl+C`.

## 4.1 Если бот падает с `telegram.error.TimedOut` / `ConnectTimeout`

Частая причина — VPN, который туннелирует только IPv4, тогда как
библиотека `httpx` сначала пытается подключиться по IPv6 и "зависает"
на этом, вместо быстрого отказа. Проверить: если
```
python -c "import urllib.request; print(urllib.request.urlopen('https://api.telegram.org', timeout=10).status)"
```
возвращает `200`, а сам бот всё равно падает с таймаутом — это оно.

**Решение:** добавьте в `.env`:
```
TELEGRAM_FORCE_IPV4=true
```
и перезапустите бота. Это заставит `httpx` использовать только IPv4,
не трогая системные настройки сети.

## 4.2 Если Telegram работает, а пересылка файлов в XMPP падает с `DNSError` / `ClientConnectorDNSError`

Это отдельная (хоть и похожая) проблема: `slixmpp` использует для
загрузки файлов (XEP-0363) библиотеку `aiohttp`, у которой свой
DNS-резолвер — пакет `aiodns`. Он посылает DNS-запросы напрямую в
обход системного DNS Windows, и многие VPN такие запросы не
пропускают, хотя обычный интернет-трафик (включая Telegram) при этом
работает нормально.

**Решение** — убрать пакет с проблемным резолвером, `aiohttp`
автоматически откатится на обычный:
```
pip uninstall aiodns pycares -y
```
После этого перезапустите бота.

## 5. Как это работает

- **Telegram → XMPP**: бот слушает сообщения в указанном чате через
  long polling. Текст пересылается как есть с именем автора. Фото,
  видео, войсы, аудио, документы и стикеры скачиваются во временную
  папку, загружаются на XMPP-сервер через **HTTP Upload (XEP-0363)**
  и отправляются собеседнику как ссылка с пометкой Out-of-Band
  (XEP-0066) — большинство клиентов, включая Monocles Chat, показывают
  такие ссылки как обычное вложение.
- **XMPP → Telegram**: входящие сообщения (текст и OOB-ссылки на
  файлы) пересылаются в Telegram-чат обычным текстовым сообщением.

## 6. Ограничения

- Один экземпляр скрипта = одна пара "чат Telegram ↔ собеседник/комната
  XMPP". Нужно несколько пар — запускайте несколько процессов с разными
  `.env`.
- Telegram Bot API не позволяет ботам скачивать файлы **больше 20 МБ**
  — это ограничение самого Telegram, а не скрипта.
- Реакции, редактирование и удаление сообщений не синхронизируются
  (можно добавить отдельно, если понадобится).
- Для продакшена бота стоит запускать под `systemd`, `supervisor` или
  в Docker-контейнере с автоперезапуском при падении/потере сети.

## 7. Хостинг

Скрипт держит постоянное соединение (long polling + XMPP-сессия), поэтому
нужен хостинг с **постоянно работающим процессом**, а не serverless/edge-функции.
Подходят, например, площадки с бесплатным веб-сервисом без обязательной
кредитной карты (сейчас это, в частности, Render — но условия бесплатных
тарифов у любых платформ время от времени меняются, поэтому перед
деплоем стоит свежим взглядом свериться с их текущими тарифами) или
недорогой VPS.
